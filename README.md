# 🛋️ نظام حمد للمفروشات والمراتب — v10

> **نظام إدارة متجر متكامل (Retail Management System)** مخصص لمحلات المفروشات والمراتب، يشمل المبيعات والمخزون والمشتريات والحجوزات والتقارير — كل ده في ملف HTML واحد يشتغل في المتصفح من غير سيرفر.

---

## 📌 نوع النظام

**هو مش POS بالمعنى التقليدي، ومش ERP متكامل — هو Retail Management System (RMS)** يعني نظام إدارة متجر تجزئة متخصص يجمع ما بين:

| الجانب                    | التفاصيل                                      |
| ------------------------- | --------------------------------------------- |
| **POS** (نقطة بيع)        | إنشاء فواتير بيع، تحصيل مدفوعات، طباعة فواتير |
| **Inventory** (مخزون)     | تتبع الأرصدة، تنبيهات النفاد، تسوية المخزون   |
| **Purchasing** (مشتريات)  | فواتير الشراء من الموردين، حساب المديونيات    |
| **Reservations** (حجوزات) | حجز بضاعة للعملاء مع تتبع التسليم             |
| **Reporting** (تقارير)    | أرباح، مبيعات يومية/أسبوعية/شهرية/سنوية، ذمم  |

---

## 🏗️ البنية التقنية

```
ملف واحد: HTML + CSS + JavaScript (Vanilla)
├── بدون فريمووركس (No frameworks)
├── بدون سيرفر (No backend / No database server)
├── البيانات محفوظة في: localStorage (المتصفح)
├── تصدير/استيراد: JSON + Excel (xlsx.js مدمج)
└── طباعة الفواتير: CSS Print Media
```

**المكتبات الوحيدة المستخدمة:**

- `xlsx.js` — لتصدير البيانات لـ Excel
- Google Fonts (Cairo, Tajawal, JetBrains Mono)
- **كل التاني كود خالص بدون dependencies**

## 🗂️ الشاشات والوحدات

### 📊 Dashboard (لوحة التحكم)

- KPIs: إجمالي المبيعات، مبيعات اليوم، قيمة المخزون
- أصناف منخفضة المخزون مع تنبيه
- آخر الفواتير المسجلة

### 🛍️ المبيعات

- إنشاء فاتورة بيع بأصناف متعددة
- خصم (نسبة مئوية أو مبلغ ثابت)
- حالة الدفع: مدفوع / جزئي / غير مدفوع
- وسائل دفع متعددة: كاش، Instapay، Vodafone Cash
- تعديل وحذف الفواتير مع تصحيح المخزون تلقائيًا
- طباعة الفاتورة

### 🏠 الحجوزات والتوصيل

- حجز بضاعة لعميل بدون خصم فوري من المخزون
- تحديد كل صنف هل "تم التحميل" (تسليم) أم لا
- خصم المخزون فقط عند التسليم الفعلي
- دعم تسليم كل الأصناف دفعة واحدة أو تدريجي

### 🛒 المشتريات

- فواتير شراء من الموردين
- إضافة المخزون تلقائيًا عند تسجيل الفاتورة
- تتبع مديونيات الموردين
- خصم على مستوى الصنف وعلى الفاتورة كلها

### 🔄 المرتجعات

- مرتجعات مبيعات ومرتجعات مشتريات
- إرجاع المخزون تلقائيًا
- ربط بالفاتورة الأصلية

### 💰 المدفوعات

- تسجيل دفعات مستقلة للعملاء والموردين
- متابعة رصيد كل عميل أو مورد
- دعم وسائل دفع متعددة

### 💸 المصاريف

- تسجيل مصاريف التشغيل (إيجار، شحن، إلخ)
- تصنيف المصاريف

### 📅 المبيعات اليومية

- عرض المبيعات بفلتر: يومي / أسبوعي / شهري / سنوي / نطاق مخصص
- إجمالي العدد والقيمة

### 📈 الأرباح والهوامش

- مقارنة سعر البيع بسعر التكلفة
- هامش الربح لكل صنف
- إجمالي الربح في فترة محددة

### ⚙️ الإعدادات والنسخ الاحتياطي

- بيانات المتجر (الاسم، المدير، العنوان، التليفون)
- إدارة الفئات، الماركات، الوحدات
- تعديل الأسعار بالجملة (بنسبة أو مبلغ ثابت)
- تسوية المخزون يدويًا
- تصدير/استيراد JSON (نسخة احتياطية كاملة)
- تصدير Excel لأي جدول
- إعادة تعيين كل البيانات

## 🔄 كيف يشتغل النظام (Data Flow)

```
المخزن (Stock)
    ↑ يزيد         ↓ يقل
 مشتريات       مبيعات + حجوزات محملة
 مرتجعات مبيعات   مرتجعات مشتريات

الرصيد المالي
 عميل: (رصيد افتتاحي + المبيعات) - المدفوعات المحصلة
 مورد: (رصيد افتتاحي + المشتريات) - المدفوعات للمورد
```

**ميزة الحماية:** النظام بيتحقق من المخزون قبل أي بيع أو تعديل، ولو المخزون مش كفاية بيرفض العملية ويرجع الحالة للأصل.

## 💾 تخزين البيانات

| ما يُحفظ | كيف |
| ------------------------ | ------------------------- |
| كل بيانات التشغيل | `localStorage` في المتصفح |
| إعداد الثيم (نهاري/ليلي) | `localStorage` |
| حالة الـ Sidebar | `localStorage` |
| نسخة احتياطية | تصدير JSON يدوي |

> ⚠️ **تنبيه مهم:** البيانات محفوظة في المتصفح فقط. لو اتمسح بيانات المتصفح أو اشتغلت على متصفح تاني، البيانات مش هتبقى موجودة. **لازم تعمل نسخة احتياطية JSON بانتظام من إعدادات النظام.**
